# 상단 바 맥락 제목 (#13)

작성: 2026-08-09

## 1. 문제

스크롤을 내리면 h1이 화면 밖으로 나가고, 그때부터 "지금 어느 글/어느 목록을
보고 있는지" 알려주는 것이 화면에 없다. 좌측 사이드바는 사이트 전체 내비게이션만
담당하고 현재 위치를 말하지 않는다.

데스크톱에는 상단 바가 아예 없다. `TopBar.astro`는 `lg:hidden`이라 좁은 화면
전용이고, 거기서도 사이트 제목만 고정으로 띄운다.

## 2. 동작

높이 56px 바가 **항상 자리를 차지하되 평소엔 완전히 투명**하다. 스크롤로 h1이
바 아래로 사라지면 배경이 반투명+blur로 켜지고 문구가 페이드로 들어온다.

`sticky top-0`을 쓴다. 자리를 차지하므로 처음 렌더 위치가 흔들리지 않고, 고정된
뒤에는 본문이 그 아래로 지나간다. 모바일 `TopBar`가 이미 이 방식이라 데스크톱이
모바일에 맞춰지는 셈이다.

임계점은 스크롤 픽셀값이 아니라 **h1의 위치**로 잡는다. `IntersectionObserver`에
`rootMargin: "-56px"`을 주어 h1이 바 높이만큼 가려지는 순간 켠다. 픽셀 상수는
페이지마다 h1 높이가 달라 어긋난다.

## 3. 문구

바는 h1을 복사하지 않는다. **그 페이지가 무엇을 하는 곳인지** 말한다. 복사였다면
빵조각을 지운 이유(h1 중복)와 같은 문제가 된다.

대분류 다섯 개는 두 종류다. `deep-dive` `study` `project`는 소분류·시리즈로
안내만 하고, `troubleshooting` `etc`는 글을 직접 나열한다. 문구도 그에 따라
갈린다 — 판정은 `listsPostsDirectly.ts`가 이미 하고 있고 새로 만들지 않는다.

| 페이지 | 문구 |
|---|---|
| 글 | 글 제목 |
| `/` | 사이트 제목 |
| `/posts` | 전체 글 목록 |
| `/categories` | 카테고리 |
| `/categories/deep-dive` (안내) | `'Deep Dive' 카테고리` |
| `/categories/troubleshooting` (나열) | `'Troubleshooting'의 글 목록` |
| `/categories/deep-dive/rendering` | `'Rendering'의 글 목록` |
| `/series` | 시리즈 |
| `/series/digitaltwin` | `'DOD로 만드는 디지털트윈' 시리즈` |
| `/tags` | Tags |
| `/tags/astro` | `'astro' 태그의 글 목록` |
| `/archives` `/search` `/about` | h1과 같은 단어 |

단어 하나인 페이지는 h1과 같은 말이 된다. 이 경우는 중복을 허용한다 — 바가
어떤 페이지에서는 말하고 어떤 페이지에서는 비는 쪽이 더 어색하다.

## 4. 값을 실어 보내는 길

`<Header barTitle="…" />`. 각 페이지가 한 줄씩 넘기고, 6줄짜리 조립부인
`Header.astro`가 `TopBar`로 넘긴다. 레이아웃 구조는 건드리지 않는다.

URL 경로를 파싱해 문구를 만드는 방법은 쓰지 않는다. 빵조각이 그렇게 만들어져
있었고, 세그먼트를 잘라 라벨로 바꾸는 특수 케이스가 계속 늘었다. 페이지는 이미
자기 라벨을 알고 있으니 그대로 넘기면 된다.

문구는 `t.bar.*` 템플릿을 거친다. 호출부에 한국어를 직접 쓰지 않는다.

## 5. 모바일

햄버거는 그대로 둔다. 위에 있을 때는 사이트 제목, 스크롤하면 문구로 바뀐다.
데스크톱과 규칙이 같아진다.

## 6. 자리 충돌

| 요소 | 지금 | 바꿀 값 | 이유 |
|---|---|---|---|
| `FloatingToc` | `sticky top-8` (32px) | `top-22` (88px) | 56px 바 + 32px 여백. 지금 값이면 바에 가린다 |
| 진행 바 | `fixed top-0 z-10` | `z-30` | 바가 `z-20`이라 그대로 두면 뒤로 숨는다 |

진행 바는 바보다 앞에 남긴다. 높이 4px짜리 실선이라 바 위쪽 가장자리에 얹혀도
문구를 가리지 않는다.

## 7. 여백

데스크톱 상단 여백이 32px(`Main`의 `pt-8`)에서 88px(바 56 + `pt-8`)로 늘어난다.
모바일은 이미 88px이었으므로 두 화면이 같아지는 것이지만, **실물로 확인하고
판단한다.** 어색하면 `pt-8`을 조정하지 말고 바 높이를 먼저 의심한다.

## 8. 범위 밖

- 바 안의 목차 버튼·프로필 썸네일 — 목차는 우측에, 프로필은 사이드바에 이미 있다
- 스크롤 진행 바의 모양 변경 — 자리(z)만 조정한다
- `Main.astro`의 `pageDesc` italic — 다음 디자인 패스에서 함께 본다
