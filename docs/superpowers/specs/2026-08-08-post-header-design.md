# 글 헤더 재구성 — 분류·날짜를 위로, 글쓴이를 아래로

작성일: 2026-08-08
선행 문서: `2026-08-07-palette-and-scale-design.md`

## 1. 배경

지금 글 페이지의 머리는 이렇게 생겼다.

```
Unity SRP에서 배치가 깨지는 이유
📅 8 Aug, 2026  |  이 글 수정
[ 연재 중 · 3/7편 ]
────────────────────────────
본문
```

문제가 셋이다.

- **이 글이 어느 분류에 속하는지 헤더에서 알 수 없다.** 사이드바를 봐야 한다.
  검색이나 외부 링크로 중간에 들어온 사람에게는 단서가 없다.
- **글쓴이가 없다.** 개인 블로그라 매번 이름을 밝힐 필요는 없지만, 글마다
  얼굴이 하나도 없으면 문서 더미처럼 읽힌다.
- **'이 글 수정' 자리가 죽어 있다.** 버튼을 제거한 뒤(`feat(post): '이 글 수정'
  버튼 제거`, 72169ba) 구분자 `|`와 `<EditPost>` 마크업이 남았고, 항상 숨김
  처리되어 아무것도 그리지 않는다.

## 2. 목표

헤더를 읽는 순서를 **"언제·어디" → "무엇" → "누가"** 로 정리한다.

```
Deep Dive › Rendering · 2026년 8월 8일

Unity SRP에서 배치가 깨지는 이유

SRP 파고들기 · 3/7편

╭───╮
│ ◕ │  Dev groot
╰───╯  Software Engineer
────────────────────────────
본문
```

헤더가 무거워지면 실패다. 메타 줄은 한 줄, 프로필은 두 줄을 넘지 않는다.

## 3. 구조

### 3.1 새 컴포넌트

`src/pages/posts/[...slug]/_components/PostHeader.astro`를 만든다. 메타 줄,
제목, 프로필을 이 컴포넌트가 모두 맡는다.

```astro
<PostHeader {post} {seriesPosition} />
```

`_components/`에 이미 `BackButton`·`ShareLinks`가 사는 패턴을 따른다.

**추출하는 이유는 재사용이 아니라 크기다.** `index.astro`는 566줄이고, 헤더
마크업이 OG 이미지 계산과 시리즈·카테고리 계산 사이에 끼어 있다. 헤더 관련
계산(대분류·소분류 라벨)도 함께 옮겨 한 곳에 모은다.

### 3.2 쪼개지 않는 이유

프로필 카드를 별도 컴포넌트(`AuthorCard`)로 미리 나누지 않는다. C묶음 #4가
사이드바 상단에 같은 사진을 쓸 예정이지만, 그 화면은 크기·정렬·링크가 다를
가능성이 높다. 두 화면의 요구가 다 보이는 시점에 쪼개는 편이 낫다. 지금
나누면 쓰이지도 않을 경계를 먼저 긋는 셈이다.

### 3.3 `index.astro`에서 걷어내는 것

- `<h1>` 블록과 날짜 `<div>` → `PostHeader`로 이동
- `<SeriesBadge>` 호출 → `PostHeader`로 이동
- `EditPost` import와 마크업 → **삭제**. #6 이후 죽은 코드다. 렌더가 **두
  군데**다 — 141-150행(데스크톱)과 176행(모바일, 본문 아래 `<hr>` 다음).
  둘 다 지우면 `hideEditPost`도 쓰는 곳이 없어진다
- `categoryLabel` 계산(84-87행)은 **그대로 둔다.** 헤더 전용이 아니라 186행의
  `<CategoryPosts label={categoryLabel} />`가 쓴다

`_components/EditPost.astro` **파일 자체는 남긴다.** 호출부가 사라져 죽은
파일이 되지만, 업스트림에서 내려온 컴포넌트라 지우면 다음 병합 때 충돌
지점이 하나 늘어난다. 콘텐츠 스키마의 `hideEditPost` 필드와 i18n의
`post.editPage` 문자열도 같은 이유로 둔다.

## 4. 메타 줄

### 4.1 구성

`대분류 › 소분류 · 날짜` 순서로 한 줄에 놓는다.

시리즈는 이 줄에 넣지 않는다. 실물을 보니 구분자에 묻히고 모바일에서 줄이
길어졌다. 6절대로 제목 아래 자기 줄을 준다.

| 조각 | 출처 | 링크 |
|---|---|---|
| 대분류 | `CATEGORIES[post.data.category].label` | `categories/{category}` |
| 소분류 | `getSubcategoryLabel(category, subcategory)` | `categories/{category}/{subcategory}` |
| 날짜 | `Datetime` 컴포넌트 | 없음 |

URL은 `getRelativeLocaleUrl(locale, ...)`로 만든다. `SidebarNav.astro`가 쓰는
방식과 같다.

### 4.2 링크는 분류만

분류 링크는 팔레트 규칙을 그대로 따른다 — 글씨는 `--link`, 밑줄만 포인트 색.

프로필 블록은 링크로 만들지 않는다. About으로 가는 길은 사이드바에 이미 있고,
이름에 밑줄이 생기면 헤더가 산만해진다.

### 4.3 구분자

`›`와 `·`는 장식이므로 `aria-hidden="true"`를 붙인다. 스크린리더는 분류명과
날짜를 각각의 텍스트로 읽는다.

## 5. 날짜

`Datetime.astro`를 세 군데 고친다. 셋 다 분기를 없애는 방향이라 코드가 준다.

**형식.** `.format("D MMM, YYYY")`를 `.format("YYYY[년] M[월] D[일]")`로 바꾼다.
이 한 줄이 글 페이지·목록 카드·아카이브를 동시에 결정하므로 사이트 전체가 한
형식이 된다. 되돌리기도 한 줄이다.

**수정일을 보여주지 않는다.** 지금은 `modDatetime`이 있으면 발행일 대신
수정일을 `수정일:` 접두와 함께 보여준다. 이 동작을 없애고 수정 여부와 관계없이
항상 발행일을 보여준다. 목록·아카이브의 정렬 기준이 발행일이므로 표시와 순서가
어긋나지 않는다.

`isModified` 분기와 `modDatetime` prop, `useTranslations` 의존이 함께 사라진다.
쓰는 곳이 없어지는 `post.updatedAt` 문자열도 i18n 세 파일에서 지운다.

JSON-LD의 `dateModified`와 `article:modified_time` 메타는 **그대로 둔다.**
`PostLayout.astro`가 담당하며 화면 표시와 무관하다. 검색엔진은 갱신 시점을
알아야 한다.

**캘린더 아이콘을 없앤다.** 사이트 어디서든 날짜는 글자만 보여준다.
`IconCalendar` import와 렌더를 지운다. 아이콘이 사라지면 켜고 끌 대상이
없으므로 스위치용 prop도 두지 않는다.

`size` prop도 지운다. `size="lg"`를 넘기던 곳이 이 작업에서 걷어낸 옛 헤더뿐이라
아무도 넘기지 않게 됐다.

타임존과 `<time datetime>` 시맨틱은 그대로 쓴다.

## 6. 시리즈 배지

시리즈는 메타 줄이 아니라 **제목 아래 자기 줄**에 놓는다. 메타 줄에 넣은
버전을 실물로 확인해보니 구분자에 묻혀 잘 보이지 않았고, 모바일에서 메타
줄이 두세 줄로 접혔다.

따라서 `SeriesBadge.astro`의 `<p>` 래퍼를 그대로 둔다. 여백만 `mt-1`에서
`mt-2`로 조정한다.

내부 로직은 손대지 않는다 — `SERIES` 조회, `current === null` 분기,
`tplStr(t.series.badge, ...)` 모두 그대로다.

이 컴포넌트는 `index.astro`에서만 쓰이므로 호출부는 한 곳뿐이다.

## 7. 프로필 블록

| 조각 | 값 | 근거 |
|---|---|---|
| 사진 | `src/assets/images/profile.png` (1254×1254) | 이미 커밋되어 있다 |
| 이름 | `config.site.title` | "Dev groot". 이미 있는 값을 쓴다 |
| 직함 | `"Software Engineer"` | 컴포넌트에 직접 쓴다 |

**직함을 설정에 넣지 않는 이유.** `types/config.ts`와 `astro-paper.config.ts`,
컴포넌트까지 세 파일을 문자열 하나 때문에 건드리게 된다. 바꿀 일이 생기면
컴포넌트 한 줄을 고치는 편이 더 쉽다.

**사진.** `astro:assets`의 `<Image>`로 48px 렌더하되 2배 해상도를 넘긴다.
`rounded-full`로 원형. `.app-prose img`에 건 `rounded-lg`는 `<article>` 안에만
적용되므로 헤더에는 영향이 없다.

**`alt=""`로 둔다.** 바로 옆에 이름이 텍스트로 있어, 대체 텍스트를 넣으면
스크린리더가 같은 정보를 두 번 읽는다. 장식 이미지로 처리하는 것이 맞다.

## 8. 엣지 케이스

| 경우 | 결과 |
|---|---|
| 소분류 없는 분류 (`project`·`troubleshooting`·`etc`) | `Project · 2026년 8월 8일`. `›`가 아예 안 나온다 |
| 시리즈가 아닌 글 | 제목 아래 줄이 통째로 생략 |

| 메타 줄이 화면보다 길 때 | 자연스럽게 줄바꿈한다. 가로 스크롤은 만들지 않는다 |

## 9. 검증

`corepack pnpm build`(0 errors) / `test`(전부 통과) / `lint`(clean)를 통과해야
한다.

빌드 통과만으로는 부족하다. dev 서버에서 네 경우를 눈으로 확인한다.

1. 소분류가 있는 글 — `Deep Dive › Rendering`이 둘 다 나오고 각각 링크로 동작
2. 소분류가 없는 글 — `›`가 없고 대분류만
3. 시리즈 글 — 제목 아래 줄에 시리즈명과 편수가 나옴
4. 수정된 글 — 발행일이 나오고 `수정일:`은 어디에도 없음

목록 카드와 아카이브도 확인한다. 5절 변경이 글 페이지 밖까지 미친다 — 날짜가
한글로 바뀌었는지, 캘린더 아이콘이 사라졌는지 둘 다 본다.

라이트·다크 양쪽을 본다.
