# 회색을 무채색으로 되돌리기

작성일: 2026-08-09
선행 문서: `2026-08-07-palette-and-scale-design.md`

## 1. 배경

사용자가 "사이드바랑 목차 색상이 너무 파란빛 도는 것 같고 눈이 아프다"고
지적했다. 측정해보니 느낌이 아니라 사실이었다.

라이트 테마의 회색 계열 채도(HSL S):

| 토큰 | 값 | 채도 | 참조로 삼았던 원본 | 채도 |
|---|---|---|---|---|
| `--muted` (사이드바 배경) | `#f3f7fc` | **60%** | `#f4f4f6` | 10% |
| `--border` | `#e1e8f2` | **40%** | `#e6e6e9` | 6% |
| `--foreground` (본문 글자) | `#2e3442` | **18%** | `#1e1f21` | 5% |
| `--link` | `#3d4453` | **15%** | `#353638` | 3% |
| `--sidebar-link` | `#9aa2b3` | **14%** | `#66666e` | 4% |
| `--muted-foreground` | `#686f80` | **10%** | `#66666e` | 4% |

색상각은 모두 213~222도, 즉 파랑이다. 원본보다 채도가 3~10배다.

`CLAUDE.md`에는 "라이트 배경 3색만 파랑 쪽으로 미세 조정했고 나머지는 원본
값"이라고 적혀 있었으나 **사실이 아니었다.** 글자색까지 전부 옮겨가 있었다.
원칙이 문서에만 있고 값에는 없으면 이렇게 드리프트한다.

## 2. 방향

**회색은 비우고 색은 포인트 하나가 담당한다.**

지금은 정반대였다. 회색에 파랑을 퍼뜨리고(채도 10~60%) 포인트는 흐렸다(채도
54%). 그래서 화면 전체가 은은하게 파랗고 정작 포인트는 덜 튀었다. 눈이 피로한
조합이다.

회색 계열을 채도 0%로 두면 같은 포인트 색이 훨씬 선명해 보인다. 색을 여러
곳에 조금씩 뿌리는 것보다 한 곳에 모으는 편이 화면이 조용하고 신호는 강해진다.

## 3. 결정한 값

### 3.1 회색 — 채도 0%

| 토큰 | 라이트 | 다크 |
|---|---|---|
| `--background` | `#ffffff` | `#171717` |
| `--muted` | `#f5f5f5` | `#212121` |
| `--border` | `#e5e5e5` | `#333333` |
| `--foreground` | `#262626` | `#e5e5e5` |
| `--link` | `#404040` | `#d4d4d4` |
| `--quote-foreground` | `#525252` | `#a3a3a3` |
| `--muted-foreground` | `#666666` | `#a3a3a3` |
| `--sidebar-link` | `#666666` | `#a3a3a3` |

### 3.2 포인트 색

| 토큰 | 라이트 | 다크 |
|---|---|---|
| `--accent` | `#8387d3` (S 48%) | `#767bd0` (S 49%, L 64%) |
| `--sky` | `#8fb4dd` | `#6e96d9` |
| `--accent-muted` | `#f4f5fe` | `#232536` |
| `--sky-muted` | `#f4fbff` | `#1a2229` |

라이트는 채도를 54%에서 48%로 살짝 낮췄다. 회색이 중립이 되면 같은 색도 더
선명해 보이기 때문이다.

**다크는 명도가 문제였다.** 78%짜리 밝은 보라가 거의 검은 배경 위에 얹혀
확 튀었다(대비 8.23). 64%로 내려 4.40이 됐다. 그 뒤 채도를 57%→49%로
낮췄더니 대비가 오히려 4.71로 올라갔다 — 어두운 배경에서는 채도를 빼면 색이
회색 쪽으로 밝아지기 때문이다. 이 경우 채도 감소는 시인성을 해치지 않는다.

`--sky`와 `--sky-muted`도 같은 방향으로 부드럽게 했다. 프로필 링과 인용문
배경의 보라→하늘 전환이 무채색 배경 위에서 도드라졌기 때문이다.

### 3.3 채도를 더 낮추지 않는 이유

포인트 색은 이제 사이트에서 색을 가진 **유일한** 자리다. 더 흐리면 회색과의
차이가 밝기만 남고, 목차 현재 위치 마커나 사이드바 활성 표시처럼 "지금
여기"를 알리는 신호가 한눈에 안 읽힌다.

무채색 배경 위의 단일 포인트 색은 보통 채도 80~90%대까지 쓴다. 48~49%는 이미
그 절반 수준이라 여기서 더 빼면 회색과 구별되지 않는다.

## 4. 명암비

전부 계산해 확인했다. 팔레트 스펙의 라이트 표에만 수치가 없어 기준 미달 값이
들어갔던 전례가 있어, 이번에는 바꾸는 값 전부를 검사했다.

**본문 크기 텍스트 (기준 4.5:1)**

| 조합 | 라이트 | 다크 |
|---|---|---|
| 본문 / 배경 | 15.13 | 14.23 |
| 링크 / 배경 | 10.37 | 12.09 |
| 인용문 글자 / 틴트 | 7.20 | 5.99 |
| 보조 글자 / 사이드바 | 5.27 | 6.38 |
| 사이드바 링크 / 사이드바 | **5.27** | 6.38 |

**비텍스트 (기준 3:1)**

| 조합 | 라이트 | 다크 |
|---|---|---|
| `--accent` / 배경 | 3.30 | 4.71 |
| `--accent` / 사이드바 | — | 4.23 |
| `--sky`(프로필 링) / 사이드바 | — | 5.39 |

**사이드바 링크는 원래 기준 미달이었다.** `#9aa2b3` on `#f3f7fc` = **2.38**로,
이번 변경 이전부터 그랬다. 5.27로 고쳤다. 대신 "흐릿하다가 hover에 진해지는"
위계는 약해졌다. 본문 크기 텍스트에서 4.5는 타협하지 않는다.

## 5. 원칙을 값 옆에 남긴다

`theme.css` 머리 주석에 두 가지를 추가했다.

- **"회색 토큰에 색상값을 넣지 마세요."** 이 원칙이 없어서 파랑이 스며들었다
- `--sky`가 "쓰이는 곳이 없다"는 설명이 낡아 있었다. 지금은 프로필 링과
  인용문 두 곳이다

## 6. 나중에 포인트 색을 바꿀 때

`theme.css`의 **여덟 줄**(라이트 4 + 다크 4)만 고치면 된다. `accent` 계열을
쓰는 파일이 21개지만 전부 토큰을 경유하며, `theme.css` 밖에 하드코딩된
색상값은 없다.

두 쌍으로 움직인다 — `--accent`/`--sky`(선명한 짝, 프로필 링),
`--accent-muted`/`--sky-muted`(연한 짝, 인용문 배경).
