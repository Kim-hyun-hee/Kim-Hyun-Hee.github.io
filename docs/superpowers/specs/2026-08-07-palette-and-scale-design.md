# 팔레트와 스케일 재설계 — 포인트 색 도입

작성일: 2026-08-07
선행 문서: `2026-08-06-blog-redesign-design.md` §7.1

## 1. 배경

### 1.1 뒤집는 결정

지금 `src/styles/theme.css` 맨 위에는 이렇게 적혀 있다.

> 블로그 UI에는 유채색을 쓰지 않습니다. 그래서 `--accent`에 본문과 같은
> 먹색을 넣었고, 강조는 색이 아니라 굵기·크기·밑줄로 냅니다.

**이 원칙을 폐기한다.** 포인트 색을 도입한다.

원칙을 세울 때 남겨둔 탈출구("색을 되돌리려면 `--accent` 값만 바꾸면 된다")가
실제로 작동하는 것을 확인했다 — 값 하나를 바꾸니 호출부 18곳이 전부 따라왔다.
다만 그대로 켜면 **글 제목까지 색이 들어간다.** 그래서 값만 바꾸는 것으로는
부족하고, 색이 어디까지 퍼질지를 함께 정해야 한다. 이 문서가 그것을 정한다.

### 1.2 함께 정리하는 것

색을 바꾸면 어차피 같은 파일들을 건드리게 되므로, 별도 감사에서 찾은 두 가지를
같이 정리한다.

- **제목 위계가 페이지마다 다르다.** h2급 제목 하나가 `2xl-semibold` /
  `2xl-bold` / `xl-semibold` / `lg-semibold` 네 가지로 갈린다. `text-lg`도
  굵기가 셋(medium / semibold / bold)이다.
- **세로 여백이 스케일이 아니라 즉흥이다.** `mt-1 / 1.5 / 2 / 3 / 4 / 5 / 6 /
  7 / 8`을 사실상 전부 쓴다. 이 중 `mt-5`·`mt-6`·`mt-7`·`mb-14`는 한두 번씩만
  등장한다.

## 2. 목표

블로그 UI의 목표는 그대로다 — 심플하고, 직관적이고, 시인성이 좋을 것. 포인트
색은 그 목표를 돕는 선에서만 쓴다. 색이 늘어서 화면이 시끄러워지면 실패다.

## 3. 팔레트

### 3.1 라이트 값

외부에서 가져온 팔레트를 우리 토큰 이름에 매핑했다. 분홍 계열
(`accent-pink` / `accent-pink-muted`)은 쓸 자리가 없어 가져오지 않는다.

| 토큰 | 값 | 역할 |
|---|---|---|
| `--background` | `#fcfdff` | 페이지 바탕 |
| `--muted` | `#f3f7fc` | 상자·사이드바 등 눌린 면 |
| `--foreground` | `#2e3442` | 본문 글씨 |
| `--muted-foreground` | `#717889` | 보조 글씨 |
| `--border` | `#e1e8f2` | 테두리·구분선 |
| `--link` | `#3d4453` | 본문 링크 글씨 |
| `--sidebar-link` | `#9aa2b3` | 사이드바 링크 |
| `--accent` | `#7e82d8` | 포인트 색 |
| `--accent-foreground` | `#ffffff` | 포인트 색 위의 글씨 |
| `--accent-muted` | `#eceeff` | 포인트 색 틴트 (**신설**) |
| `--sky` | `#79c8ea` | 그라데이션 짝 (**신설**) |
| `--sky-muted` | `#eaf8ff` | 그 틴트 (**신설**) |

가져온 팔레트에는 `surface: #ffffff`가 따로 있었지만 **가져오지 않는다.**
페이지 바탕(`#fcfdff`)과의 차이가 RGB로 2밖에 안 나 사실상 구분되지 않고,
지금 우리 상자(관련 글 상자, 사이드바)는 눌린 면으로 디자인돼 있어 그 값을
쓸 자리가 없다. 쓰지 않을 토큰을 만들면 다음 사람이 "이건 언제 쓰나"를
고민하게 된다. 카드를 밝은 면으로 뒤집고 싶어지면 그때 추가한다.

### 3.2 다크 값 (파생)

가져온 팔레트에는 다크 값이 없다. 색상각과 채도를 유지하고 명도만 뒤집어
만든다. 지금 팔레트도 같은 방식으로 만들어졌다.

| 토큰 | 다크 | 배경 대비 |
|---|---|---|
| `--background` | `#16181f` | — |
| `--muted` | `#232733` | — |
| `--foreground` | `#e6e9f0` | 14.7:1 |
| `--muted-foreground` | `#9aa1b2` | 6.9:1 |
| `--border` | `#2e3342` | — |
| `--link` | `#c9cedb` | — |
| `--sidebar-link` | `#9aa1b2` | — |
| `--accent` | `#a5a8ea` | 8.0:1 |
| `--accent-foreground` | `#16181f` | — |
| `--accent-muted` | `#2b2f4a` | — |
| `--sky` | `#8fd2f0` | — |
| `--sky-muted` | `#1c2a35` | — |

다크에서도 상자(`#232733`)가 페이지(`#16181f`)보다 밝다 — 라이트에서 상자가
페이지보다 어두운 것과 방향은 반대지만, 둘 다 "바탕에서 한 단계 떨어져 나온
면"이라는 의미는 같다. 지금 팔레트도 같은 방식이다.

`--link`는 두 테마 모두 본문 글씨보다 대비를 한 단계 낮춘 값이다 — 지금
팔레트가 지키던 관계를 그대로 옮겼다. `--sidebar-link`는 라이트에서
`--muted-foreground`보다 밝고, 다크에서는 같은 값이다. 이것도 지금과 같다.

### 3.3 없어지는 토큰

- `--brand` — 보관해둔 파랑. 보라가 그 역할을 가져가므로 지운다.
- `--tag-hover` / `--tag-hover-foreground` — 태그 칩 hover가 `--accent-muted` +
  `--foreground`로 처리되므로 필요 없어진다.

## 4. 색을 어디에 쓸까

### 4.1 원칙

**포인트 색은 "표시"에 쓰고 "본문 크기 텍스트"에는 쓰지 않는다.**

- **표시** — 선, 테두리, 배경 틴트, 밑줄, 아이콘, 진행 바, 활성 인디케이터,
  선택 영역
- **텍스트** — 제목·링크·목록 항목. `--foreground` 또는 `--link`를 쓴다

근거 셋:

1. 참고한 디자인이 실제로 그렇게 쓴다. 인용문도 선과 배경만 포인트 색이고
   글씨는 회색이다.
2. `#7e82d8`은 흰 배경에서 **3.4:1**이다. 본문 크기(4.5:1 필요)에 쓰면 흐리다.
3. 글 제목에 색을 넣지 않기로 했다.

**예외:** 24px 이상 큰 글씨는 기준이 3:1이라 통과한다. 현재 해당하는 곳은 404
페이지의 거대한 숫자 하나뿐이다.

### 4.2 지금 색이 들어간 곳의 처리

| 위치 | 바꾼 뒤 |
|---|---|
| 글 제목 `h1` | `--foreground` |
| 카드 제목 (글 목록) | `--foreground`, hover 시 **밑줄만** 포인트 색 |
| 분류 목록·시리즈 목록의 항목 제목 | 위와 같음 |
| 분류 페이지의 소분류 제목 | 위와 같음 |
| "더 보기" 링크 | `--link` + 포인트 색 밑줄 |
| 목차 현재 위치 | 글씨는 `--foreground` 굵게 + **좌측 세로선** 포인트 색 |
| 사이드바 사이트명 | `--foreground` |
| 사이드바 활성 분류 | 지금도 `--foreground` — 유지 + **좌측 마커** 포인트 색 |
| 상단 스크롤 진행 바 | 포인트 색 유지 |
| 텍스트 선택 영역 | 포인트 색 유지 |
| 포커스 링 | 포인트 색 유지 |
| 404 숫자 | 포인트 색 유지 (§4.1 예외) |
| 시리즈 현재 편 `▸` 마커 | 포인트 색 |
| 태그 칩 hover | 먹색 반전 → `--accent-muted` 배경 + `--foreground` 글씨 |

**링크 처리가 이 설계의 핵심이다.** 글씨는 먹색으로 두고 밑줄만 색을 칠하면,
색이 존재감을 내면서도 읽기를 방해하지 않는다.

### 4.3 인용문

본문 인용문(`blockquote`)을 포인트 색과 그라데이션이 실제로 쓰이는 자리로
만든다. 지금은 `border-s-accent/80 opacity-80` — 좌측 선과 흐림뿐이다.
`opacity-80`은 걷어낸다. 글씨 색을 직접 정하므로 투명도로 흐리게 만들 이유가
없고, 투명도는 배경 그라데이션까지 함께 흐리게 만든다.

- 좌측에 3px 세로선 — `--accent`
- 배경 — `--accent-muted`에서 `--sky-muted`로 가는 가로 그라데이션
- 글씨 — `--muted-foreground`
- 오른쪽 모서리만 둥글게

다크에서는 두 틴트가 다크 값으로 바뀌면서 같은 효과가 난다.

## 5. 제목 위계

네 갈래로 갈린 것을 세 단계로 고정한다. 굵기는 두 개만 쓴다.

| 단계 | 규격 | 쓰는 곳 |
|---|---|---|
| 페이지 제목 | `text-2xl sm:text-3xl` · `font-bold` | 글 제목, 모든 페이지 제목 |
| 섹션 제목 | `text-xl` · `font-semibold` | 홈 섹션, 분류 페이지의 소분류 |
| 항목 제목 | `text-lg` · `font-semibold` | 카드 제목, 목록 항목 |

`font-medium`은 제목에서 쓰지 않는다. `font-bold`는 페이지 제목 전용이다.

## 6. 여백 스케일

세로 여백을 네 단계로 줄인다.

| 값 | 용도 |
|---|---|
| `2` | 붙어 있는 요소 사이 (라벨↔값) |
| `4` | 블록 사이 |
| `8` | 섹션 사이 |
| `12` | 큰 구획 |

바꾸는 것: `mt-3` → `2` 또는 `4` (자리에 따라), `mt-5` → `4`, `mt-6` → `8`,
`mt-7` → `8`, `mb-14` → `12`.

아이콘·배지 옆의 `gap-1` / `gap-1.5` 같은 미세 간격과, 이미 스케일에 맞는
`mt-1` / `mt-1.5`(라벨 바로 아래 붙는 줄)는 그대로 둔다.

## 7. 함께 고쳐야 하는 문서

- **`src/styles/theme.css` 상단 주석** — "유채색을 쓰지 않는다"는 원칙 설명이
  통째로 거짓이 된다. §4.1의 새 원칙으로 다시 쓴다.
- **`src/styles/typography.css:39-40` 주석** — "강조색은 파랑, 본문 링크는
  무채색"이라고 적혀 있다. 파랑이 아니라 보라이고, 링크는 무채색이 아니라
  같은 색 계열의 회색이 됐다.
- **`CLAUDE.md`의 "색 운용 원칙" 절** — 이 파일은 git에 커밋되지 않지만,
  다음 세션의 작업 기준이 되므로 반드시 갱신한다.

## 8. 범위 밖

가져온 블록에는 색 외에 폰트(Pretendard), 본문 폭 920px, 페이지 여백 40/24px,
라운드 4단계(10/14/20/999px), 트랜지션이 함께 있었다. **이번에는 색만
가져온다.** 색만 바꿔도 인상이 크게 달라지므로, 그 상태를 보고 나머지를
판단하는 것이 순서다.

분홍 계열 두 값은 쓸 자리가 없어 아예 가져오지 않는다. 필요해지면 그때
추가한다.

## 9. 완료 기준

- 라이트·다크 양쪽에서 §3의 값이 그대로 적용된다
- 글 제목, 카드 제목, 목록 제목 어디에도 포인트 색이 들어가지 않는다
- 링크는 글씨가 먹색이고 밑줄이 포인트 색이다
- 목차 현재 위치와 사이드바 활성 분류가 좌측 마커로 표시된다
- 태그 칩 hover가 연보라 배경이 된다
- 본문 인용문에 좌측 선과 그라데이션 배경이 들어간다
- 404 숫자를 제외하면 24px 미만 텍스트에 `--accent`가 쓰이지 않는다
- 제목이 §5의 세 단계 밖으로 나가지 않는다
- 세로 여백에 `mt-3` / `mt-5` / `mt-6` / `mt-7` / `mb-14`가 남아 있지 않다
- `--brand` / `--tag-hover` / `--tag-hover-foreground`를 참조하는 곳이 없다
- §7의 문서 세 곳이 갱신됐다
- `corepack pnpm build`, `corepack pnpm test`, `corepack pnpm lint`가 통과한다
